# 3D 渲染入门

## 什么是渲染

**渲染（Rendering）** 是把三维场景计算成二维图像的过程。一个三维场景包含四样东西：

| 要素 | 说明 |
| --- | --- |
| **模型（几何）** | 物体的形状，如立方体、角色、场景 |
| **材质** | 表面的属性：颜色、粗糙度、金属度、透明度等 |
| **灯光** | 光源的位置、强度、颜色 |
| **相机** | 观察视角、焦距、构图 |

渲染器按照光学规则，为画面中的**每一个像素**计算出它应该呈现的颜色，最终输出一张图片或一段序列帧。

> 📷 类比：渲染就像给「虚拟影棚」里的物体**拍照**——相机决定构图，灯光决定明暗，材质决定表面质感，渲染器负责按下快门并冲印。

## 实时渲染 vs 离线渲染

| 类型 | 特点 | 用途 |
| --- | --- | --- |
| **实时渲染** | 每帧必须在几十毫秒内完成（配合 30/60 fps），使用大量近似算法 | 游戏、VR、Blender 视口预览 |
| **离线渲染** | 不限制时间，可以算几分钟到几小时，追求物理精确 | 影视特效、产品渲染、最终出图 |

> 💡 两者的界限在模糊：硬件光追让实时渲染越来越强，但「要快还是要精」的取舍始终存在。

## Blender 的两种渲染器：Eevee vs Cycles

| | **Eevee（实时）** | **Cycles（物理）** |
| --- | --- | --- |
| **计算方式** | 光栅化 + 屏幕空间效果（近似） | 路径追踪（模拟真实光线传播） |
| **速度** | 极快，可实时交互 | 慢，需等待采样收敛 |
| **间接光** | 近似（靠 Irradiance Volume 烘焙） | 自动精确计算 |
| **反射/折射** | 近似，效果依赖屏幕信息 | 真实精确 |
| **焦散** | 无 | 有 |
| **材质质感** | 一般，偏「游戏风」 | 逼真 |
| **适用** | 预览、动画快速检查、游戏资源展示 | 最终出图、产品、影视级画面 |

**怎么选**：

- 想**快速看效果**、做动画预览 → Eevee
- 想要**逼真的最终成图** → Cycles

## 渲染的基本流程

```text
建模 → 材质 → 灯光 → 相机 → 渲染设置 → 出图
```

顺序不是绝对的：可以先调好渲染器和相机，再慢慢补灯光材质。关键是**最后出图时**检查四样东西都齐了：模型有材质、场景有灯、相机对着物体、渲染器设置正确。

## 游戏/实时渲染的整体流程（与 TA 结合）

上一节的流程是「一次渲染一张图」。但在游戏等实时项目里，一条资产要经过更长的**生产流水线**才能变成屏幕上的最终画面——而这个流水线上，有一类叫 **技术美术（Technical Artist，简称 TA）** 的角色在各个环节起作用。

### 一条资产到最终画面的完整流程

```mermaid
flowchart LR
    A[概念设计] --> B[高模 / 低模]
    B --> C[UV 展开]
    C --> D[贴图烘焙<br>法线 / AO]
    D --> E[PBR 贴图制作]
    E --> F[导入游戏引擎]
    F --> G[材质 / Shader 实现]
    G --> H[灯光 + 后处理]
    H --> I[性能优化<br>LOD / 剔除 / 光照烘焙]
    I --> J[最终画面 / 打包发布]
```

### 技术美术（TA）是什么

TA 是**既懂美术又懂技术**的人，充当美术与程序之间的桥梁：

- **美术侧**：建模、贴图、灯光、动画都要懂（能理解美术想表达什么）
- **程序侧**：Shader、渲染管线、脚本、引擎功能都要会（能把美术需求翻译成引擎能实现的东西）
- **核心职责**：让美术「能做出想要的效果」，让程序「不用为美术的细节反复返工」

> 💡 一句话：程序告诉美术「引擎有什么限制」，美术告诉程序「我想实现什么」，TA 负责把两边接通并做出可用的东西。

### TA 在流程各环节的职责

| 阶段 | 美术（建模师/原画） | 技术美术（TA） |
| --- | --- | --- |
| **建模 / UV** | 建模型、展 UV、控制拓扑 | 定规范：面数预算、UV 密度、命名规则 |
| **贴图 / 材质** | 制作 PBR 贴图 | 写 Shader、建材质库、定贴图格式与分辨率标准 |
| **导入引擎** | 把资产拖进引擎 | 写导入/导出工具、自动化批处理、校验资产质量 |
| **灯光 / 后处理** | 调灯光、摆场景 | 搭建后处理栈（色调映射/景深/Bloom）、写自定义特效 |
| **性能优化** | — | 做 LOD、设置遮挡剔除、烘焙光照、出性能报告 |
| **文档 / 培训** | — | 写技术文档，教美术团队用引擎特性 |

### 想走 TA 方向，需要补什么

对照当前知识库，你可以这样一步步积累：

1. **渲染原理**：PBR、法线贴图、光照（从本知识库的 PBR / 法线贴图 / 灯光笔记入手）
2. **Shader 入门**：Blender 材质节点 → 引擎的 Shader Graph → 逐步接触代码
3. **引擎操作**：Unity 或 Unreal 二选一，先熟悉资源导入和材质系统
4. **一门脚本语言**：Python（做 DCC 工具、批处理最通用）
5. **性能思维**：面数、Draw Call、贴图内存这些概念先有意识，实操中再加深

> 🎯 对零基础来说：先扎实做好「建模 → 材质 → 渲染」的每一步，再往 TA 方向延伸，基础不牢的技术栈是空中楼阁。

## 关键概念与参数

### 采样（Samples）

- 每个像素投射到场景的**光线数量**。采样越多，噪点越少、画面越干净，但渲染越慢。
- 常用范围：`128 ~ 1024`（室内复杂光照可能更高）。
- Cycles 自带**降噪（Denoise）**，可以在较低采样下获得干净画面——不要盲目堆采样。

### 光线追踪 / 路径追踪

- **光追**：追踪光线从相机出发、经过物体表面、到达光源的完整路径，模拟光的反射、折射。
- Cycles 用的是**路径追踪（Path Tracing）**，每根光线在表面弹跳多次（Bounces），次数越多越真实但也越慢。

### 分辨率

- 输出图像的像素大小，`1920×1080`（1080p）、`3840×2160`（4K）。
- 渲染时间是像素数的正比——**4K 是 1080p 的 4 倍时间**，从低分辨率开始测试很明智。

### GPU vs CPU

- **GPU（显卡）**用并行计算做光追，通常比 CPU **快几倍到几十倍**。
- Blender 设置：`编辑 → 偏好设置 → 系统 → Cycles 渲染设备`，勾选显卡：
  - NVIDIA 卡：`CUDA` 或 `OptiX`（推荐 OptiX）
  - AMD 卡：`HIP`
  - Intel 卡：`oneAPI`
- 有独显一定要开，渲染速度天差地别。

### 色彩空间（View Transform）

- **Standard（标准）**：直出，高光容易过曝。
- **Filmic（胶片）**：自动压缩高光动态范围，画面更像照片，默认推荐。
- **AgX**：Blender 4.x 新增，比 Filmic 色彩还原更准。

## 第一次渲染出图：实操步骤

1. **打开 Blender 默认场景**：自带立方体、面光、相机，可以直接练手。
2. **选渲染器**：顶部菜单切到渲染引擎，先试 **Eevee**（快）再试 **Cycles**（准）对比效果。
3. **调整相机**：小键盘 `0` 进入相机视图，用 `G`/`R` 调整相机位置朝向，把立方体框进画面。
4. **确认有灯光**：默认场景有一盏面光，可以选中它移动、调强度（属性面板 `Strength`）。
5. **按 `F12` 渲染**：Blender 渲染当前相机视角。
6. **保存**：渲染窗口点菜单 `图像 → 另存为`，选 PNG 保存。

> 🎯 练手目标：渲染出第一张带光影的图。然后试着改材质颜色、加一盏灯、换 Cycles 对比，感受两者差异。

## 踩坑记录

- ❌ **渲染出来全黑**：场景没灯光 / 相机没对着物体 / 物体法线反了（蓝色朝内）。
- ❌ **渲染特别慢**：采样拉太高、没开 GPU、分辨率太大——先降低参数看效果。
- ❌ **画面噪点多**：采样不够，开 **Denoise（降噪）**，或增强灯光（灯光不足噪点最严重）。
- ❌ **Eevee 反射/阴影效果差**：Eevee 是近似渲染，追求真实就换 Cycles。
- ❌ **渲染和视口不一样**：视口是实时预览，渲染是完整计算，两者正常会有差异。
- ❌ **忘了开 GPU**：默认可能用 CPU 渲染，独显白费。
